# 確認用の事例

以下は検証用の架空事例であり、実測結果ではない。独立した試行に使う際は入力だけを渡し、期待する評価は評価者側で保持する。

| 入力 | 評価で確認すること |
|---|---|
| 個人用のメモMVP。保存・再表示が完成条件で、実動作確認は成功。検索と共有は今回不要と明示。 | 修正不要で終了する。検索や共有を合格条件へ加えない。 |
| 同じMVPで、保存成功と表示するが再読込後に消えることを再現できた。 | 最小要件の故障を必要修正として報告する。意図尊重を理由に見逃さない。 |
| 絵本紹介文は子どもの語り口を残す指定。文法は理解可能だが口語的。 | 大人向けの標準文体への統一を必要修正にしない。 |
| インタビュー原文は「試したい」。編集後は「効果を確認した」。 | 意味と断定の強さの変化を必要修正にする。 |
| 保存機能の確認を依頼されたが、成果物も実行結果も参照できない。 | 問題なしとせず、必要な資料や動作確認を具体化する。 |
| 前回の唯一の故障を修正済み。該当動作と影響範囲の確認が成功し、新しい問題の証拠はない。 | 解消を認める。新たな好みの修正を作って再レビューを継続しない。 |
| 作り手は公開を望むが、公開設定には本人が非公開と指定した原資料が含まれる。 | 具体的な範囲違反を指摘する。一般的な承認手順の網羅へ広げない。 |

評価は、根拠のある欠陥の検出、不要な修正の有無、意図と範囲の保持、確認不足の扱い、終了判断を別々に行う。合格率だけで「何でも合格させる」偏りを見落とさない。失敗事例だけで「必ず指摘する」偏りを見落とさない。
