# 二層への再設計と4スキルの確認

2026-09-14。改訂前はcommit `c33c3fdd93d2b135da8e8b1b3f94fdf06fd69d60` に保存されている。

## 人間の希望

対話から育てた意図が、禁止事項の反復へ戻ることへの指摘があった。人間の制作動機と、エージェントに託す目的は主語が異なるため、両方を残す。Dialogue Essayの編集方法は思考・適応に適用し、状態・記録・検証には具体的な手続きを使う。これは対話の要約であり逐語引用ではない。

今回の依頼は、新しいDialogue PromptでCheckerとPublisherを作り直し、支持する独立版Essayをそのまま同梱して、新しいCheckerで4つを確認すること。

## Codexの具体化

新しいPromptの手順に沿い、素材と目的を確認し、人間の制作動機、エージェントの判断、操作条件を分けてCheckerとPublisherを執筆した。以下はその対応である。

| 人間の希望・既存条件 | 設計判断 | 操作と確認 |
|---|---|---|
| 粘土細工を元の塊へ戻したくない | Checkerは選んだ特徴と完成条件から判断する | 必要修正・確認不足・任意拡張を分け、根拠が揃えば終了 |
| 実際の不具合は見つけたい | 意図と故障を区別する | 対象箇所・根拠・影響・最小対処を示す |
| 対話の方向修正を活かしたい | 新しい評価軸と以前の結果を分ける | 変更理由を記録し、再確認は修正と波及範囲に絞る |
| 希望の媒体・形態を聞き、配布時は白紙 | Publisherは完成原稿の届け方を共有する | 未指定項目を確認し、外部の非公開設定へ保存 |
| 意味と帰属を保って届ける | 内容の制作と媒体用の整形を区別する | 原稿と掲載結果の対応を確認 |
| 重複や意図しない通知を避ける | 結果不明を完了にしない | URL・IDで照合し、未送信確認まで再送せず、未確定なら停止 |
| ログを引き継ぎ、将来移行したい | 本文は参照し、操作を記録する | 識別子・日時精度・確認結果を保持。移行送信は依頼範囲に従う |

目的を先に説明する配置へ改めた。権限、意味の保持、送信不明時の停止、完了条件は引き継いだ。再送は「未送信と確認できるまで再送しない」と明確化した。SDKやモード名は対象の仕事に必要な場合だけ扱う。

Essayは独立リポジトリ `kentaroid-bot/dialogue-essay` のcommit `57673cac97872caa9991167ab2288e926723a7ea` にあるスキルフォルダ全体を無改変で同梱する。Essayをほかの3つと同じ見出しへ統一することは、今回の依頼に含まれない。

## 新しいCheckerによるレビュー

対象は4スキルの本文・現行の付属資料・呼び出し設定。基準は今回の意図、必要な運用条件、参照の成立である。Codexが新しいCheckerの入力・判定・完了手順で行う自己レビューであり、独立モデルによる実行試験ではない。

| 対象 | 判断と根拠 |
|---|---|
| Prompt | 制作動機を独立させ、思考と手続きの編集方法を分け、判断から操作・確認への対応を要求している。具体的な権限と仕様の保持もある。 |
| Checker | 粘土の動機を残し、完成を認める判断と実際の故障の指摘を両立する。レビューと変更の範囲、根拠不足、終了条件を扱う。 |
| Publisher | 希望を聞く動機を残し、白紙設定、原稿の意味、既存記事の照合、通知範囲、結果不明時の停止、媒体別の完了、操作記録を扱う。 |
| Essay | 指定された独立版とのファイル集合・内容一致を確認した。人間の着想をまとまって展開し、AIの評価を別に置く原版の構成を保つ。 |

Checker付属の7事例について、完成済MVP・口語の保持・修正済みの再レビューは完成判断へ、保存故障・断定の変更・非公開資料の公開は必要修正へ、資料不足は判断保留へ対応することを本文と照合した。これは設計上の確認であり、7回のモデル実行結果ではない。

4スキルの形式検証が成功し、現行のローカルリンクに欠落がなく、PublisherのJSONテンプレートが有効かつ白紙であること、Essayの4ファイルが原版とバイト単位で一致することを確認した。旧版比較資料の移動前リンクは歴史資料として対象外とする。実媒体への試験投稿や性能比較は今回のレビュー範囲に含めない。

判定：今回の目的に照らし、4つとも修正不要で次へ進める。収録元のMITライセンスが配布物に必要なため、`LICENSE-dialogue-essay` を追加し、READMEに出典と参照先を記載した。
